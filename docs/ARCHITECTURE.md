## 配置所有权

1. 分享链接的原文存于节点 `sourceText`，原生出站存于 `outbound`。
2. 托管模板只在连接或预览时生成运行快照，不反写节点。
3. 原生完整配置保存原始文本，运行时不经过模板。
4. 编辑器草稿不立即写入已保存配置；保存操作完成语法检查，不冒充内核校验。
5. 节点本地编辑设 `locallyEdited`，订阅更新不覆盖该对象。
6. 内核覆盖若与原生出站格式不同会报错，不能靠丢弃字段实现转换。
7. 所有启动请求必须先通过对应内核检查，状态以实际子进程为依据；它不代表远端节点一定可连通。
8. 托管运行快照可以添加统计、解析规则缓存路径并为 TUN 分配独立名称；这些修改不会反写节点。完整原生配置不做此类注入。

## 持久化

桌面版保存至 Tauri `app_local_data_dir` 下的 `workspace.json`，通常为 `%LOCALAPPDATA%/io.anibox.desktop/`。
正常文件系统使用临时文件原子替换，并通过后端互斥锁串行写入。Windows 重定向或虚拟文件系统若返回跨卷错误，则先保留上一份恢复副本，再使用兼容写入。浏览器预览使用独立 localStorage key。
读取失败不会以空工作区覆盖原文件。背景压缩为最多 1920px 的 JPEG 数据，随工作区持久化。

系统代理在 `system-proxy-lease.json` 中记录修改前和预期修改后的值。停止或下一次启动时，仅在当前值与应用写入值一致的情况下恢复。其他软件后续修改过时放弃恢复所有权。
GUI 崩溃时 Job 对象负责停止子进程，代理恢复仍需下一次启动应用；独立 watchdog / Windows 服务留待下一阶段。

## TUN

GUI 在普通权限下生成请求，通过 `runas` 启动同一程序的 `--tun-helper` 分支。
请求限于本应用的数据目录；控制端只监听本机地址，使用 Windows 随机数生成的令牌认证。
helper 在启动内核前再次校验配置，使用隐藏的独立控制台和 Job 对象持有内核。
停止时在该独立控制台发送退出信号，等待清理；超时才强制终止。控制连接关闭时也执行停止。

托管接口使用随机 `Anibox-xxxxxxxx` 名称，补充清理仅作用于这种生成接口。
清理失败的记录在下一次授权启动 TUN 时重试。原生配置的接口名不自动改写，生命周期主要由其内核负责。
长期 Windows 服务和不同管理员账户代授权尚未实现。

## 规则与统计

内置 `assets/rules` 中的两份大陆 SRS，首次复制到用户缓存。
下载使用固定 HTTPS 源、大小限制、SRS 头检查和实际 sing-box 校验。
新文件成对写入新的代际后再更新索引；下载失败保留旧代际。历史代际暂不自动删除，以保留原生配置中的明确路径引用。
应用启动 30 秒后检查更新，运行中每小时检查是否已达到 24 小时更新间隔。应用退出后不运行。
网络请求异步；缓存读写、内容比较、内核校验在阻塞线程池中执行。内容相同只更新时间戳，不重复启动校验进程。
自动更新当前只覆盖 SRS。Xray DAT 随内核提供，尚未接入更新。

托管 Xray 使用随机本机端口的 Metrics 与入站统计；sing-box 使用随机端口及认证令牌的 Clash API。
读取累计计数后按时间差计算速率，同一进程内累加；进程变化或停止时重置采样。
只累计 Xray 入站计数以防重复计算，排除管理入站。原生配置只读取它已有的本机统计端点。
一秒一次的界面轮询有并发保护，上一轮未完成时跳过下一轮。

## 预留接口

- **新协议**：添加分享链接适配器，返回原生出站和错误信息；无法完整表示的参数显式拒绝。
- **内核策略**：扩展 `coreForNode` 为版本化能力矩阵，输入包括协议、传输、节点偏好和连接模式。
- **规则资源**：SRS 下载与缓存已实现。后续增加 DAT 更新、更多分类与缓存清理；保持原生配置路径引用有效。
- **TUN**：认证提权进程已实现。后续可替换为长期服务，前端继续通过 DesktopBridge 发起请求。
- **更新**：增加 ReleaseProvider / CoreRepository，使用官方发布元数据、完整性检查、暂存、兼容校验和回滚；不要直接覆盖运行中的文件。
- **统计与日志**：真实速率与总量已实现；后续增加内核日志流。未配置统计的原生配置继续显示不可用，不生成模拟数据。
- **存储**：保留 `version` 字段；引入数据库或 DPAPI 时编写显式迁移，不在加载失败时重置数据。
- **订阅**：增加协议解析器注册表、稳定的源节点标识和更新差异预览。现有合并用名称、协议、服务器和端口匹配；源节点重命名可能被视作新增。

## 连接阶段

`取得原生配置 → JSON 检查 → 内核 check → 启动进程 → 检查提前退出 → 如需要，检查 HTTP 入站并设置系统代理 → 报告运行状态`

TUN 则在内核校验后进入提权进程分支，不设置系统代理。原生配置自身包含 TUN 时也会进入该分支。

系统代理模式只接受绑定 127.0.0.1 的无认证 HTTP / mixed 入站；不会向公网监听。
第二次启动由单实例插件唤起已有窗口，不重复接管网络。
